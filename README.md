# Git Updater Core

A lightweight, generic, and zero-dependency WordPress plugin designed to seamlessly manage and apply updates directly from public or private GitHub repositories. 

Unlike heavy alternatives, this plugin uses native WordPress core update transients and hooks, ensuring maximum compatibility, fast load times, and a highly secure updater life cycle.

## Features

- **Generic Implementation:** Automatically detects any plugin containing the custom `GitHub Plugin URI` header entry.
- **Subdirectory Shifting Support:** Fully supports plugins housed within monorepos or custom nested repository directory structures.
- **Smart 12-Hour Transient Caching:** Prevents GitHub API rate-limiting exhaustion by caching response payloads locally.
- **Granular Security Whitelisting:** Scan and explicitly authorize which GitHub organization or user handles are permitted to push updates via the WordPress Admin UI.
- **Private Repository Readiness:** Optional Personal Access Token (PAT) input fields to securely fetch and update code from private repositories.
- **Clean Execution Architecture:** Decouples core functional updating hooks from administrative configurations scripts.

## Installation

### Manual Installation from GitHub ZIP

1. **Download the Package:**
   - Navigate to the GitHub repository of this updater.
   - Click the green **Code** button and select **Download ZIP** (or navigate to the **Releases** tab and grab the latest production `.zip` source archive).

2. **Upload to WordPress:**
   - Log in to your WordPress administrative dashboard (`/wp-admin`).
   - Navigate to **Plugins > Add New Plugin** and click the **Upload Plugin** button at the absolute top of the viewport interface.
   - Choose the downloaded `.zip` file and select **Install Now**.

3. **Activation:**
   - Once successfully extracted by the server engine, click **Activate Plugin**.
   - Navigate to **Settings > GitHub Updater** to configure your deployment preferences.

## Targeted Plugin Header Configurations

To hook any custom destination plugin into this update distribution engine, simply declare the targeted environment metrics inside your plugin's main header comment block.

### Example A: Standard Plugin in Root Directory
*Perfect for basic standalone public repositories.*

```php
<?php
/**
 * Plugin Name:       My Custom Extension
 * Version:           1.0.4
 * GitHub Plugin URI: https://github.com/org-or-owner/repo
 */
```

### Example B: Advanced Nested Plugin with Release Compilation Assets
*Perfect for monorepos or build-process workflows where deployment-ready distributions are uploaded as formal release assets.*

```php
<?php
/**
 * Plugin Name:       Monorepo Distribution Extension
 * Version:           2.1.0
 * GitHub Plugin URI: https://github.com/org-or-owner/repo
 * GitHub Updater Source: release
 * GitHub Plugin Subdirectory: packages/production-build/
 */
```

### Header Definitions Mapping
- `GitHub Plugin URI`: *Required.* The canonical absolute web browser URL mapping to your core remote GitHub repository workspace.
- `GitHub Updater Source`: *Optional.* Choice values limited to `tags` or `release`. 
  - `tags` (Default fallback): Downloads the source code zipball natively generated by GitHub when a tag is pushed.
  - `release`: Instructs the engine to search through the `releases/latest` endpoints specifically tracking an uploaded, pre-compiled `.zip` attachment asset.
- `GitHub Plugin Subdirectory`: *Optional.* The inner relative tracking path leading to the target plugin's files block if the root directory of the repository does not align with your WordPress plugin's structural architecture layout.

## Configuration & Usage

Once your targeted plugins possess the required headers, manage distribution rights instantly through the dedicated admin workspace:

1. **Authorize Owners:**
   - Navigate to **Settings > GitHub Updater** inside your WordPress dashboard.
   - The engine automatically scans all active headers and aggregates distinct repository owners inside the **Allowed GitHub Owners** section.
   - Check the explicitly allowed users/organizations and save configurations to avoid authorization hijacking from 3rd-party repositories (e.g., preventing external plugins containing identical generic header configurations from overriding core paths).

2. **Personal Access Tokens (PAT):**
   - If managing private production modules, generate a classic personal access token possessing strict `repo` scope permissions within your personal GitHub Profile settings.
   - Supply the alphanumeric string inside the **GitHub Token (PAT)** input block. Leave blank if managing purely public workspaces.

3. **Triggering Update Checks:**
   - Click the **Refresh Updates** secondary button action anytime to purge local 12-hour transient caches and force immediate live version synchronizations.
   - Any available version updates will cleanly render inside the standard native **Dashboard > Updates** panels alongside official WordPress.org notifications.
